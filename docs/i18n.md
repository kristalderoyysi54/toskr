# 界面多语言（中文 / English）

## 机制

- `src/lib/i18n/index.ts`：中文原文即 key。`t("暂停 15 分钟")` 中文环境原样返回，英文环境查 `src/lib/i18n/en/*.ts`。
- `t()` 的参数类型是英文字典的 key 联合：**新增中文文案必须同时在英文字典里加条目，否则 typecheck 失败**。
- 插值：`t("已删除 {n} 条", { n: count })`；英文复数写 `{ one: "Deleted {n} item", other: "Deleted {n} items" }`，按 `vars.n === 1` 选择。英文占位符必须与中文 key 完全一致（单测校验）。
- React 节点插值：`tNode("按 {key} 发送", { key: <kbd>⌘⏎</kbd> })`。
- 日期：`toLocaleString(intlLocale(), …)`，不要再写死 `"zh-CN"`。
- 语言来源：设置 `language: system | zh | en`；主面板解析后 `publishLocale` 写 localStorage + 广播事件，并 `api.setLocale` 下发 Rust（托盘、窗口标题，见 `src-tauri/src/i18n.rs`）。默认中文，测试环境无需任何改动。

## 改造规则

1. 用户可见的中文都要过 `t()`：JSX 文本、`aria-label`、`title`、`placeholder`、`tip()` / `undoableTip()` 文案、确认框文案。
2. **key 必须与现有中文逐字一致**，中文环境输出不得有任何变化（大量测试断言中文）。模板字符串改成 `{name}` 占位后，中文输出也要逐字一致。
3. 组件内用 `const t = useT();`（订阅语言切换），**每个渲染文案的组件都要自己调用**，memo 组件尤其不能依赖父组件重渲染。非组件代码（store、lib、事件回调里的 tip）直接 `import { t }`，调用时求值。
4. 模块级常量里的文案（选项数组、`Record<…, string>` 标签表）不能在模块加载时求值：存中文 key（类型 `MessageKey`），渲染时 `t(item.label)`；或改成函数。
5. 参与逻辑比较的中文（联合类型取值、`=== "全部"`、按文案查 DOM、持久化字段）保持中文不动，只在**显示处**翻译。
6. 不翻译：注释、`api.diagNote` / 诊断日志、`console`、测试文件、写入用户数据的默认值（如默认分组名——属于用户数据）、识别中文文本的正则、AI 提示词（第二轮单独处理）。
7. 字典按区域分文件（`en/<区域>.ts`），只往自己区域的文件加条目。`en/common.ts` 已有的通用词直接用，不重复添加；不同区域出现同一 key 时译文必须一致（单测校验）。
8. 内置对象名（收件箱 / 收集箱 / 剪贴板 / 秘文 / 未命名分组、稳妥发送等内置发送方案、「通用」提示词组）在数据里存中文：**显示**分组名一律 `sectionName(section)`，发送方案名 `profileName(profile)`，提示词组名 `promptGroupName(group)`（`src/lib/i18n/builtinNames.ts`）；比较、存储、发给 AI 的仍用原始 `.name`。改名输入框的初值用显示名，提交时与显示名相同则不写回。
9. 新建时才生成的用户数据（新分组名、新笔记占位等）可以在创建时用 `t()` 生成当前语言版本；但被正则/相等比较识别的内容（如 format.ts 的 `图片 N 张` 占位）保持中文。

## 英文文风

- 面板宽 380–500px：英文务必简短，能用短词不用长句；按钮 1–2 个词。
- 按钮、菜单项、页签、分组标题用 Title Case（`Send Selected`）；设置行标签、说明、提示气泡用 Sentence case（`Clear clipboard history`）。
- 中文全角标点换成英文标点；保留中文里的 `…`（表示会弹出后续界面）；保留 `⌘⏎` 等按键符号。
- 产品名、应用名、Platinum 等原样保留。
