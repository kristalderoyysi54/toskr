# 手动验收清单

发布前逐项过一遍（涉及全局键盘、焦点、剪贴板与多屏行为，自动化难以覆盖）。

1. 任意 App 双击 ⇧ ⇄ 面板滑出/收起；出现在光标所在屏
2. 划词双击 ⇧ → 面板不弹、气泡闪现、卡片入库、原剪贴板不破坏
3. 大写打字/长按/组合键不误触发；设置改双击 ⌃ 后 ⇧ 失效 ⌃ 生效
4. 连拍捕获显示 ×N；重复内容提示已存在不重复入库
5. 气泡悬停出现「撤销」，点击后卡片移除；移开恢复穿透
6. iTerm/终端前台双击 ⇧ → 面板吸附其右缘同高；拖动/缩放窗口实时跟随；切到 Safari 回退屏幕右缘
7. 「把当前应用加入伴随列表」生效；终端半屏靠右时面板左收钳制屏内
8. ⌘F 搜索命中高亮/计数/清空；Esc 分层退出
9. ↑↓/Space/Enter/⌘⌫/⌘A 全键盘操作；拖拽把手 Space 键盘排序
10. 删除/合并/清理已完成 → toast 撤销恢复原位
11. 已完成沉底折叠展开；顶栏清理按钮
12. 跨组拖拽；拖到折叠组悬停自动展开
13. 当前 Target Profile 的回车策略为“关闭”：从 TextEdit/Codex 打开 Toskr，勾选 synthetic 文本发送 → 只粘贴、不回车；成功 HUD 的应用名与实际目标一致，卡片才标完成
14. 发送前退出目标 App → `blocked/target_exited` 气泡；无粘贴、无回车，卡片未完成、选择与面板恢复
15. Pin 面板 → 切 App B → 回面板发送 → 落点只允许为 B；切换后旧 token 不得继续投递到 A
16. 仅在一次性 TextEdit 文档中把精确 Profile 设为“允许自动回车”：文本粘贴后、200ms 回车窗口内抢焦点到 App B → B 无粘贴且两边都无回车；结果为 focus drift，卡片与选择保留
17. iTerm/终端作为目标且保持默认设置 → 只粘贴、不自动回车；确认设置默认值仍为关闭
18. 全屏 Safari/终端上双击 ⇧ 面板与气泡均可见
19. 隐身模式开启：捕获入库但无气泡
20. 宽度拖拽调节并重启记忆
21. 导出完整备份 → 删卡 → 预检并恢复；发送按钮悬停预览与实际粘贴一致
22. 三步上手引导逐项打勾并庆祝；重启数据完整；单实例聚焦

## 剪贴板事务（Phase 02）

23. TextEdit 新建含粗体、颜色与链接的富文本并复制 → 向另一应用发送一条 Toskr 文本 → HUD 显示原剪贴板已恢复 → 回到空白 TextEdit 粘贴，文字与 RTF/HTML 样式保持一致
24. Finder 同时复制两个测试文件 → 完成一次 Toskr 发送 → 在临时空目录粘贴，两个文件均可复制且顺序/类型未退化为纯文本
25. Preview 复制一张图片 → 完成一次发送或复制回退捕获 → 使用“从剪贴板新建”，图片内容与尺寸仍一致
26. 分三次发送，在 Toskr 写入后约 100ms、500ms、1400ms 复制新的 synthetic 文本 → 每次最终剪贴板均保留新文本，HUD 显示“已保留你刚复制的内容”
27. 先复制 sentinel，再在目标应用取消选区并触发捕获 → 不新增历史 sentinel 卡片；原剪贴板仍可粘贴 sentinel；另在可延迟复制超过 500ms 的应用复测，迟到内容不得入库且宽限窗内原 sentinel 被恢复
28. 在实际偏慢的聊天应用发送文本/图片 → 内容成功落入目标；约 1.5s 后原剪贴板恢复，期间手动复制的新内容不被覆盖

## 数据事务、完整备份与媒体完整性（Phase 02A）

29. 设置 → 数据 → 预检一个临时空目录：确认只显示“迁移当前数据 / 取消”；迁移后主窗口立即展示原记录与图片，活动目录更新，重启后内容与媒体仍一致
30. 预检另一个含有效 Toskr 数据的临时目录：记录/任务/媒体数量可见；分别验证“加载目标”“取消”和二次确认后的“创建恢复点后替换目标”，两个有效数据集不出现自动 merge
31. 预检默认目录：默认目录为空时显示迁移语义；已有有效数据时显示加载/显式替换语义；完成后主窗口与 Settings 显示同一活动目录，重启不出现旧快照
32. 在复制、验证、指针提交或重新水合期间制造失败（测试包/故障注入）：原目录指针、原内存与目标已有数据均恢复；目标不被半成品识别为活动目录
33. 应用打开期间用外部编辑器改动 `toskr-data.json`，再在 Toskr 编辑：旧内存不得覆盖磁盘；设置页出现“重新加载 / 另存恢复副本后加载 / 暂不处理”，三条路径均不静默采用最后写入者
34. 导出 `.toskr-backup`，在全新临时目录导入：notes、tasks、sections、taskSections、允许备份的设置、图片数量与内容 hash 一致；归档中搜索不到 AI API Key，导入确认也明确提示需重新配置
35. 导入旧 `.json`：预检明确提示可能缺媒体与 taskSections；创建当前数据恢复点后才合并；导入结束运行健康检查，不把旧 JSON 描述为完整备份
36. 清理含图片的剪贴板历史后立即撤销：图片仍可显示；等待撤销/GC 宽限结束并重启，仍被其他 Note/Task 引用的同名图片不得删除
37. 数据健康检查构造缺失、孤立、共享和撤销栈引用媒体：只显示数量与修复建议，不自动删除缺失记录或无法确认的孤立文件
38. 数据操作“冻结/重新水合”覆盖层可见时尝试双击捕获、剪贴板推送、详情保存、键盘删除和修改设置：所有写入均被阻止，操作完成或回滚后恢复
39. 使用故障注入包分别在 recovery/staging 持久化、旧目标搬移、指针提交、前端 rehydrate、rollback recovery copy 后强制退出：重启只恢复或继续同一 operation ID；外部新版本不被删除，journal 未完成前普通写入仍禁止
40. 将自定义数据目录暂时离线或让默认数据 JSON 损坏后启动：应用进入 recovery-only 界面而不是静默回默认/直接退出；“重试挂载”与“选择并加载另一个有效目录”可用，普通编辑仍只读
41. 备份或目录预检显示 A 后，在确认窗期间用测试进程原地替换成另一份同 schema 的 B：load、replace、migrate、完整恢复与旧 JSON 合并均以 `externalConflict` 停止，不按 A 的计数宣称处理了 B
42. 在数据冲突后另存恢复副本：若当前媒体仍匹配内存记录的内容寻址文件名则导出成功；若同名 PNG 已被外部替换，必须拒绝生成“记录 A + 图片 B”的伪完整备份
43. 对两张到期墓碑执行 GC，并分别在 journal 落盘、文件隔离、隔离文件删除后强制退出：重启能恢复或完成；重复排期不能把墓碑重绑定到同名外部新文件，后一文件冲突时前一文件也回放
44. Native 数据事务已经提交指针、等待前端 rehydrate 时单独重载 main WebView：启动协调器在开放写入前续接或回滚 pending operation；完成后 hydration、启动 GC 与运行时设置只执行最终目录版本
45. 在目标数据的快捷键/剪贴板监听/主题等运行时设置下发过程中注入失败：native finalize 不早于全部设置命令；回滚后只保留旧目录设置，界面解除只读前不出现两批 IPC 交错
46. 外部冲突发生后重载或晚打开 Settings：冲突状态仍持久可见，“重新加载 / 另存恢复副本后加载 / 暂不处理”可聚焦；普通设置 patch 仍被 main 权威写闸拒绝

## Target Lens 投递目标可视化（Phase 03，RUNTIME-REQUIRED）

47. 分别从 TextEdit 与 Codex 打开 Toskr：Target Lens 的图标、应用名、“可发送”状态与 Profile 回车策略准确；发送落点、成功 HUD 应用名与 Lens 一致
48. Pin 面板后从 App A 切到 App B：Lens 只更新为 B，不清空当前选择、草稿或预览；发送只能落到 B，不能回投 A
49. 伴随/磁吸仍指向 App A 时切到 App B：Lens 反映 B 而不是停靠对象；开关伴随和停靠方向不改变投递目标语义
50. 在独立窄面板、右/左侧边栏、上/下横向条分别检查 ready / refreshing / blocked：目标条不横向滚动、不变成厚重工具栏，长应用名可截断，阻断原因仍可见
51. 目标 App 退出或 PID/launch identity 变化且 Toskr 仍在前台：Lens 自动转为阻断；笔记、任务、批量、预览和快捷键入口均不粘贴、不回车，HUD 与 VoiceOver 给出同一原因
52. 快速 A→B→A 切换并连续点“重新识别”：旧异步响应不得回滚新目标，图标不闪回、相同快照不重复请求图标或制造事件风暴
53. 使用缺少图标的测试 App：显示稳定 fallback；键盘可聚焦并触发“重新识别”；VoiceOver 精确读出目标名、状态与 Profile 的格式/回车/隐私策略
54. 在一次性 TextEdit 文档分别配置 Profile 的“关闭 / 确认 / 允许”回车策略：Lens 即时更新，实际发送分别只粘贴 / 确认后回车 / 直接回车；焦点漂移时仍由 Native gate 阻断

## Target Profile 与 Prompt 分组（Phase 04，RUNTIME-REQUIRED）

55. 设置分为“目标与模板”（Profile 管理 + Prompt 分组/模板）与独立的“伴随停靠”分区；两区均键盘可达，深链 snippets → 目标与模板、companion → 伴随停靠
56. 用 v8 临时数据启动新包：旧 Prompt 的非冲突 ID、名称、正文和顺序全部保留并归入“通用”；重复/空 ID 稳定重编号但不丢模板；旧 autoEnter=true 只迁为默认 Profile 的“发送前确认”
57. 分别为 Codex、Claude、浏览器配置精确 Profile，再逐个切换：Lens 的 Profile、Prompt 分组、格式、回车和隐私策略随真实 bundle 命中；未配置应用显示安全默认
58. 逐个切换仓库既有终端 bundle：默认“终端（安全）”Profile 命中，回车始终关闭；应用未安装的 bundle 留在配置中也不导致设置页崩溃
59. 把同一 synthetic bundle 加入两个 Profile：设置页与 Lens 同时警告，按列表首项稳定命中；上下移动后 winner 可预测变化
60. 在 App A 手动选择“本次 Profile”，快速切到 App B 再回 Toskr：临时选择不被覆盖，但所有发送入口先阻止并显示“目标已变化，请确认 Profile”；确认后才可发送
61. 删除正被 snippet 和多个 Profile 引用的分组：全部引用回落“通用”，HUD 报告修复数量，重启后无孤儿引用
62. 在 380pt 竖面板与横向条用 VoiceOver/Tab 检查 Lens Profile 下拉、确认按钮、重复命中警告和 SelectionBar“当前分组 / 全部模板”，不得横向溢出或隐藏回车状态

## 签名与 TCC 备注

构建使用本机自签名证书 **"Toskr Dev Signing"**（`bundle.macOS.signingIdentity`），签名跨编译稳定，重新编译后无需重新授权辅助功能。换机器时：先在钥匙串创建同名代码签名证书并信任，或移除该配置退回 ad-hoc（每次重编译需在系统设置里删掉 Toskr 条目重新添加）。`pnpm tauri dev` 的调试进程权限附着于启动它的终端。

## AI 智能（v0.9.x 新增）
63. 设置 → AI 智能：预设点选填 Base URL（模型名为空才带入推荐值）；API Key 默认遮罩、眼睛可切换；「测试连接」未启用也能跑，成功/失败各有气泡
64. 任务输入框 ✨ 模式：「下午3点提醒我开会」回车 → 生成带到期时间的任务；AI 未配置/断网时按原文创建普通任务（输入不丢失）+ warn 气泡；💡 与 ✨ 互斥
65. 任务右键「AI 拆解子任务」→ 写入 3-8 条检查项，HUD 可撤销；笔记右键「AI 转任务」→ 建任务删笔记一次撤销恢复；「AI 起标题」→ 卡片通栏出现短标题
